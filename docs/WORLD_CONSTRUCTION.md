# 地形・道路・建設・ゾーニング仕様 v1.0

> **ゲーム内ルールの正本。** 完成形は [GAME_DESIGN](GAME_DESIGN.md)。個体の移動・信号処理の厳密なStateとEventは [TRAFFIC_VERTICAL_SLICE](TRAFFIC_VERTICAL_SLICE.md) / [RUNTIME_PROTOCOL](RUNTIME_PROTOCOL.md) を優先する。実装状況ではなく目標動作を記す。

## 1. ワールドの物理的な単位

| 項目 | v1基準 |
| --- | --- |
| ワールド座標 | メートル単位の右手系座標（座標系の軸対応は描画実装時に固定）。ゲーム内位置の正規表現はProcess側 |
| 地形・ゾーニングの基本セル | 一辺8 m。地形レイヤーと区画レイヤーは同じ座標基準 |
| セルのチャンク | 32×32セル = 256 m四方。地形/区画の差分更新・LODとセーブのまとまり |
| 初期開発可能領域 | 1024×1024セル = 約8.192 km四方 |
| 全体の最大解放領域 | 2048×2048セル = 約16.384 km四方 |
| 標高 | 地形高さは0.25m単位の量子化を初期案とし、実際の描画メッシュは補間してよい |
| ネットワーク | 道路/歩道/線路/電線/上下水管は別の有向グラフ。見た目上接していても接続点がなければ接続しない |
| マップ境界 | 都市外の道路/鉄道/水路/貨物と接続する専用のExternalPortを置く |

**数値は発売版の初期コンテンツ仕様**。マップサイズが大きいだけで毎フレーム2048²セルを評価しない。地形編集やサービス更新は影響チャンク/接続成分だけを失効・再計算する。

各マップは地形seed、初期地形、資源、水域、初期外部接続、気候帯を持つ。初期4マップ：平原、河川、海岸、丘陵。解放タイルは隣接を条件に選び、プレイヤーは高価な遠隔飛び地を初期から自由に買えない。最初の都市開始画面でマップseed、左右通行、難易度、自然災害、施設解放方式を設定し、その値をセーブへ固定する。

## 2. 地形と造成

- 地形は高さ・勾配・地表用途・地下資源・水域参照・適性revisionを持つ。近隣の建物位置や道路の工事可否は地形に従う。
- 造成はブラシで整地・盛土・切土を行う。確定前に土量/費用/影響する建物・道路・水路をプレビュー。
- 既存の建物下や通行中の道路を無断で貫く地形変更を認めない。撤去/再建を促すか、接続と安全性が保てる専用工事へ誘導。
- 河川・湖・海は水面高さと水域マスクで表す。v1はゲームルール上の取水・汚染・洪水が中心であり、全セルの高精度な3D流体物理は行わない。
- 地形の編集後に `TerrainChanged(area, revision)` を発行。接する道路の高さ条件、区画適性、排水先、影響水域を差分再評価する。

## 3. 道路ネットワーク

道路ツールは始点・終点/中間点を指定し、直線と曲線を敷設する。接続先へのスナップ、既存道路との交差、橋/トンネルの切替、建設できない理由をプレビューする。

| 種別 | 基本車線 | 速度制限の初期値 | 目的 |
| --- | ---: | ---: | --- |
| 生活道路 | 双方向2車線 | 30 km/h | 住宅の接道、低交通量 |
| 集散道路 | 双方向4車線 | 50 km/h | 地区間を接続 |
| 幹線道路 | 双方向4〜6車線 | 60 km/h | 都市の主動脈 |
| 一方通行 | 2車線 | 40 km/h | 商業街・都心回遊 |
| 高速道路 | 双方向4車線以上 | 90 km/h | 外部接続と長距離移動 |
| 歩行者専用道 | 車両通行なし | 歩行用 | 公園・駅・商業歩行者軸 |
| バス優先車線 | 専用車線の追加属性 | 元の道路に従う | 公共交通の時間短縮 |

速度・車線数は初期コンテンツの基本値。実際の所要時間は混雑、信号、天候、事故、政策で変わる。道路タイプの**実効交通容量**は長さ・車線数・信号サイクル・車種構成から求め、具体係数はゲームバランスデータに置く。

道路には `RoadSegmentId / RoadNodeId / BoundaryId` を設ける。交差点は一つの巨大なオブジェクトで全処理を行わず、車両進入・歩行者横断・右左折競合の条件を持つ境界として解決する。

- 道路変更・切断は影響する経路の版を上げ、予約移動を失効して必要なIDだけ再予測/再経路化する。
- 既に走行中の車が切断された区間から突然消滅しない。工事で閉鎖される車両は手前停止/迂回待機/安全な退避をゲームルールとして処理。
- 左側通行と右側通行を新規都市の設定として選択可能。交差点の進入経路・右左折・車線・標識の描画へ一貫して反映する。

## 4. 歩道・横断歩道・交差点・歩道橋

- 生活道路・集散道路・幹線道路は原則歩道を自動生成。高速道路には一般歩道を自動生成しない。
- 歩道と横断歩道は独立した歩行グラフ。自動横断歩道は接続/進路/信号条件を満たす交差点に配置。手動追加・削除も可能。
- 歩道橋と地下歩道は高さの異なる歩行区間として接続。段差により施設へアクセスできない問題を通知。
- 歩行者が横断歩道へ入る前にState不一致から `CrosswalkWaiting` へ移り、青かつ入場可能なら `CrosswalkWalking`。横断途中の通常の赤で停止せず、出口で `SidewalkWalking` に戻る。
- 車が横断歩道の競合領域へ入る前に、歩行者・車両信号・競合・容量を一度確認。通行不可なら理由付きWaitState。解除イベントで再試行。
- 信号なし交差点は優先道路・横断者優先・衝突領域の許可で判断。表示範囲に依存せず同じ結果。

より細かなState、早着/遅延、排他領域・容量の扱いは [TRAFFIC_VERTICAL_SLICE](TRAFFIC_VERTICAL_SLICE.md) を参照。

## 5. ゾーニング

基本用途は**住宅 Residential / 商業 Commercial / 工業 Industrial / オフィス Office** の4系統。

| 用途 | 密度/専門化 | 主な条件 | 生み出すもの |
| --- | --- | --- | --- |
| 住宅 | 低・中・高 | 接道、電力/水、入居需要、騒音/汚染/地価 | 世帯と人口 |
| 商業 | 低・高 | 接道、商圏の購買需要、物流、雇用 | 商品・サービスと雇用 |
| 工業 | 一般・農業・林業・鉱業の専門化 | 輸送、労働力、原料/電力、汚染許容 | 製品・雇用・貨物 |
| オフィス | 標準・高密度 | 教育水準、アクセス、通信・電力、需要 | 事務/高度雇用・税収 |

1セル=8mの塗りゾーン。区画内の道路に接するセルから**奥行き4セルを標準的な建築候補の上限**として扱う（特殊施設/高密度テンプレートは別）。同じ敷地は二つの建物へ重複占有させない。

区画指定は**土地の用途を決めるだけで、すぐ建物を完成させない**。建物は需要、建築適性、接道・インフラ・資金/開発条件から一定の建設時間を経て完成する。

## 6. 建物のライフサイクルと建設

標準的なState:

`Planned → UnderConstruction → Operating → (Upgrading / Vacant / Degraded) → (Operating / Abandoned / Demolishing)`

- 住宅/商業/工業/オフィス建物は区画から自動的に選定・成長。公共施設やユニーク施設はプレイヤーが建物テンプレートを直接配置。
- 建物レベルは原則1〜3。密度、アクセス、地価、教育、汚染、サービス、需要の組み合わせで成長を判断し、条件が継続する期間が経過したらアップグレードする。即時レベル上げはしない。
- 建設中は人口・雇用・税収の容量へ未稼働として数えない。完工イベントで容量が追加される。
- 退去やサービス停止では空室・稼働低下が生じる。長期間の悪条件で放棄。条件が回復すれば再利用/改修できる。
- 撤去は受入可能な代替住宅/就業施設への移動Stateを設定し、既存のIDを無断消去しない。建物・道路の所有関係と予約はProcessで解決する。
- 公共施設は維持費と定員があり、予算変更で稼働率が変化する。定員超過は待機/代替施設へ流す。

### 建設操作と料金

1. UIで道路・区画・建物・インフラを選択。
2. 半透明プレビューに**用地、接続、傾斜、建設費、維持費、既存建物への影響**を表示。
3. プレイヤーが確定すると `CityCommand` をProcessが検証。可なら元帳へ支出と土地/道路の変更を一度だけ反映。
4. 複数施設の配置計画中は**未確定の計画を取り消し・修正**可能。確定済みの施設は撤去/再開発を使う。
5. 設置できない場合、UIはProcessの理由（資金不足・接道なし・水域・急傾斜・通行止めの問題・区画不適合等）を表示。無言で拒否しない。

費用は `基本費×規模 + 地形造成費 + 橋/トンネル等の追加費` とする。維持費は設置面積/長さ/施設種類と予算水準に依存。数値は [GAME_BALANCE_RELEASE](GAME_BALANCE_RELEASE.md) のデータ表を基準にし、コードに散在させない。

## 7. 区画・道路の変更が何を更新するか

`RoadChanged → RoadGraphRevision → 接道判定/経路キャッシュ失効 → 建築適性/需要/アクセススコア差分更新`

`ZoneChanged → ZoneRevision → 建物候補/建築需要更新`

`TerrainChanged → TerrainRevision → 工事/道路/排水/浸水の影響範囲更新`

一つの大工事をしただけで**無関係な都市全域の全IDを再評価しない**。区間→影響集団、敷地→建物、設備→接続成分などの逆引き索引を利用する。

## 8. 完了判定

- 新規マップを開き、道路・歩道・住宅/商業区画・電力/上下水を置くと建物が時間経過で入居/稼働する。
- 接道のない区画には自動建築されず、理由を見られる。
- 交差点で歩行者・車が同じ競合領域を不正に二重使用しない。
- 道路切断/造成/撤去後にも住民・車両IDが不意に消失せず、適切に待機/迂回する。
- 初期8.192km領域から段階的にマップを解放でき、保存/ロードで位置・土地・道路グラフが変化しない。
- カメラを向けていない地区でも工事が進み、建物状態・人口・アクセスが正しく変わる。
