# バランス初期値・性能目標・完成判定 v1.0

> **完成品の受入仕様**。ここに記す値は「採用する初期値・検証すべき目標」であり、性能を計測済み・難度を実証済みという意味ではない。プレイテストによって調整する場合は根拠とデータ版を記録する。最初の交通コアの検証は [VALIDATION_PLAN](VALIDATION_PLAN.md) を優先。

## 1. 設定値はコードに固定しない

数値はゲームの一貫性を保ちながら調整できるよう、データ定義として外部化する。各数値には単位、最小/最大、有効なState、参照される計算ルール、変更時のキャッシュ失効対象を設定する。

### 初期設定値（Normal）

| パラメータ | 値 | 単位と意図 |
| --- | ---: | --- |
| 初期資金 | 500,000 | Credit |
| 資金の最小単位 | 0.01 | Credit（内部では64bit整数の最小単位で保持） |
| 住宅税率 | 9 | % |
| 商業/工業/オフィス税率 | 10 / 10 / 10 | % |
| サービス予算初期値 | 100 | % |
| サービス予算調整幅 | 50〜150 | % |
| 1xの1ゲーム日 | 5,400 | SimClock秒（実時間90分） |
| 時間倍率 | 停止、1、2、4、8 | イベントはどの速度でも時刻順に実行 |
| 自動保存 | 10 | 実時間分。5世代保持 |
| 区画セル | 8 | m四方 |
| 地形チャンク | 32×32 | 区画セル |
| 最大マップ | 16.384×16.384 | km |
| 住民個体の同一性 | 64bitのID | 人口の人数カウンタに置換しない |

ゲーム内「1日」は `86400` 暦秒だが、その1日を `5400` SimClock秒で進める。**イベントは必ずSimClockの単一時刻へ変換して予約し、二時計を独立に再生しない。**

## 3. 数量の保存とプレイヤーの理解を両立する

都市ゲームの数値は現実の厳密な工学モデルではなくてもよい。しかし表示される結果は説明・検証可能でなければならない。

| 計算 | 必要な整合性 |
| --- | --- |
| 人口 | 住民総数＝生存しているCitizenIdの数。出生/転入/死亡/転出で差分が一致 |
| 世帯 | 全世帯が有効な所属を持つ。住戸定員を超えない |
| 交通 | 区間/車両/駅/交差点に同時入場したIDが二重計上されない |
| 在庫 | 期首在庫＋生産＋入荷−販売−廃棄−出荷＝期末在庫 |
| 電力/水 | 供給・需要・損失・未供給が矛盾しない |
| 財政 | 期首残高＋確定入金−確定支出＝期末残高 |
| 公共施設 | 利用中数≤使用可能定員。閉鎖/退去で枠を適切に解放 |
| 地区 | 土地の区域指定・集計が重複して総人口や税収を増やさない |
| 時刻 | 予約イベントの時刻順・旧版失効・同時刻の安定順序が守られる |
| 描画 | カメラ位置/描画FPSが人口・交通量・課税・災害の論理結果へ影響しない |

**見た目の雑さは許容するが、ゲームの意味論の破綻は許さない。** 例えば1000人が同じ歩行規則を使っても誰が曲がったかを特定でき、画面外で車が横断歩道に進入するときも信号条件を守る。

## 4. 推奨動作環境とパフォーマンスの受入目標

初期の基準PC（**設計上の検証環境、動作保証ではない**）:

- 6コアクラスCPU（例: Ryzen 5 5600 / Core i5-12400）
- メインメモリ16GB
- 6GB程度のVRAMを持つ専用GPU（例: GTX 1660クラス）
- SSD、1920×1080解像度
- Windowsを基準とし、Linux/macOSでは等価な負荷条件で検証する

### リリース前の目標

| シナリオ | 設計上の合格目標 |
| --- | --- |
| 人口10万人、現実的な道路・公共交通・経済・サービスがある都市 | 1080p中設定で平均60FPS、95パーセンタイルのフレーム時間20ms以内 |
| 人口100万人、現実的な都市構成・通勤ピークを含む | 1080p低設定で平均30FPS、95パーセンタイルのフレーム時間40ms以内 |
| 10万人・100万人での1xの時間進行 | SimClockが壁時計に対して継続的に遅れない。処理過負荷ではスキップせず速度制限を明示 |
| 人口100万人のゲーム本体メモリ | プロセスの通常利用量8GB以内を初期目標。セーブ/ロード時のピークは別計測 |
| 手動セーブ | 10万人で15秒以内、100万人で60秒以内を初期目標（SSD基準） |
| 安定性 | 10万人で連続10時間、100万人で連続2時間の自動操作ソークテストでクラッシュ/不変条件違反なし |
| 論理再現性 | 同じseed/入力/シミュレーション版から正規WorldStateの比較が一致する |
| 大規模化 | 1万・10万・100万IDのベンチマークで、共有率とイベント数・GC・再計算頻度を記録して性能理由を説明できる |

これらは**未検証の目標値**。発売前に比較可能な都市データ・測定環境・グラフィック設定・JVMバージョンを固定して評価し、達成できない場合は基準を無断で「達成済み」に変更しない。実測と設計上のトレードオフをIssueに記録して判断する。

### ゲームの軽量化で先に手を付ける場所

1. 現在のStateを区間・時間帯・規則で共有し、個体ごとの定期更新を減らす。
2. 最早到着バッチとイベント予約で、通過予定時刻まで計算を休止する。
3. 逆引き索引で道路・信号・設備変更の影響範囲だけを再予測する。
4. 遠方の描画はLOD・インスタンス・密度上限で減らし、論理移動は継続する。
5. 無効予約の蓄積、キュー・ID配列・GC、経路探索の再計算回数、保存時の負荷を実測する。
6. 解像度を落とすときも信号や建物定員などの**ゲーム上の整合性**を落とさない。

## 5. ゲーム機能の完成判定（Definition of Done）

機能を「完了」と呼ぶには以下をすべて満たす必要がある。

- [ ] **仕様:** 目的、入力/出力、制約、State、発生/解除イベント、どの集団を共有計算するかが明記。
- [ ] **Process:** ゲームのルールと不変条件が実装され、ヘッドレステストで通る。
- [ ] **UI:** プレイヤーが操作でき、なぜ成功/失敗したかを表示できる。
- [ ] **Data:** セーブ/ロードで正しく復元され、版・参照エラーが安全に扱われる。
- [ ] **OOP/UPD:** 具象クラス継承禁止、オーバーロード禁止、final強制、移譲、1クラス1責務、1関数1処理、ネスト制限、カプセル化、三層責務分離を守る。
- [ ] **性能:** 画面外で全IDの高頻度更新を要求せず、コア性能計測に対象機能を追加。
- [ ] **ローカライズ:** 日本語・英語のUI名称、エラー、ヘルプ、ツールチップがある。
- [ ] **テスト:** 通常、境界、失敗、容量同時競合、表示非依存、セーブ再開を検証。
- [ ] **観測:** 正しく動いているか判断できる計測・ログまたはUI指標がある。

## 6. エンドツーエンドの完成シナリオ

### E01: 街が生まれる

マップを選択→道路を外部接続→区画を塗る→電力/水/下水を整備→住宅に世帯が入居→就職→通勤→商店で消費→都市に税収が入る。**入居・建設・通勤・税収がカメラ外でも進む**。

### E02: 交通問題を解く

人口増→朝の通勤渋滞→横断歩道の待ち/車の信号・容量を正しく処理→バス路線・鉄道を整備→交通手段の再選択→混雑率が下がり住民満足度が改善。車両と歩行者の重複なし。

### E03: インフラ停止から復旧する

発電所故障→送電系統停電→水ポンプと工場稼働低下→地区の住宅満足度・売上が低下→予算と発電/送電の修理→電力と水が復帰→各系統の容量と税収が回復。イベントの連鎖が無限に発生しない。

### E04: 財政難から復活する

維持費増→赤字→税・予算・公共交通を見直し→借入/再開発→生活の質を維持しながら黒字へ。残高、借入、税率、施設容量、住民満足度の変化が説明できる。

### E05: 災害と復興

洪水/火災で道路・建物・ライフライン停止→避難と救急/消防→影響する経路予約失効→修復工事→住民帰宅。カメラを他地域へ移しても被害・復旧は進む。

### E06: 大都市のスケーラビリティ

現実的な人口10万/100万都市（職場・学校・買い物・交通・電力・施設・汚染あり）で通勤ピークをシミュレーションし、性能目標と状態保存則を測る。住民や車の単なる「静止データ100万件」のみで合格扱いしない。

## 7. 本番QAと配布の判定

- [ ] 新しい都市からチュートリアル完了まで、ブロッカーなし。
- [ ] サンドボックスで全主要施設カテゴリを建設・稼働・撤去可能。
- [ ] 初期シナリオ5本について達成・失敗・続行の動線が正常。
- [ ] 地形・道路・建物・人・車・交通機関の接続・衝突・保存を検証。
- [ ] 大都市の経済・人口・交通が少なくとも数日間にわたり破綻しない。
- [ ] 主要画面・シナリオ・エラーが日本語・英語で利用可能。
- [ ] 設定（再割当、文字サイズ、アクセシビリティ、音、画質）を変更しても保存・操作性に問題なし。
- [ ] ランダムなセーブ/ロードや電源断の模擬試験で元のセーブを破損させない。
- [ ] Windows / Linux / macOSの配布対象ごとの実行・描画・入出力・署名/検証を確認。
- [ ] 配布物の署名、SHA-256、Artifact Attestation等の真正性確認を既存の [#1](https://github.com/tomiya7688/city-builder/issues/1) に従って完了。未署名/未検証の最終成果物をリリースしない。
- [ ] 全外部素材・ライブラリのライセンスと配布条件が確認できる。
- [ ] 重大なデータ消失/クラッシュ/不変条件違反/リソースリークがリリース判定時点で未解決でない。

**設計の完成とソフトウェアの完成は別**。この文書の性能値・品質ゲートは未達でも「仕様を定義した」状態にはできるが、「完成したゲーム」として公開する条件にはならない。

## 8. 残すべき判断と変更管理

設計上の初期値は固定して先へ進める。ただし次の事項は実際のプレイ・ベンチでのみ最終確定する。

- ゲーム内1日の速度、通勤/建設/出生・転入のバランス。
- 建物/道路の価格、税収と維持費、公共施設の容量と救済手段。
- ODキャッシュ、集団最早イベント索引、GC・並列化の実装、描画ライブラリの選択。
- 100万人時の最終表示密度とグラフィック品質。
- 最低スペックとサポートOSでのリリース可否。

変更する場合、**数値はデータ版と調整根拠**、**動作仕様はこの文書と該当ドキュメント/Issueの変更差分**を残す。測っていない性能やプレイバランスを完了済みと表記しない。
