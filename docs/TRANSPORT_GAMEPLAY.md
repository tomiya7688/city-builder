# 道路・歩行者・自家用車・公共交通・物流のゲーム仕様 v1.0

> 完成版交通のプレイ仕様。交通の厳密な境界リクエスト・信号・競合領域・早着/遅延は [TRAFFIC_VERTICAL_SLICE](TRAFFIC_VERTICAL_SLICE.md)、IDとイベント順は [RUNTIME_PROTOCOL](RUNTIME_PROTOCOL.md) が正本。こちらは交通政策・経路選択・運行・交通手段のゲームルールを定義する。

## 1. 交通のゴール

都市内の移動は**交通手段を問わず同じ「出発地→目的地→境界ごとの遷移」モデル**に接続する。道路・歩道・鉄道・駅・停留所・港等はそれぞれ別のルールを持つ接続グラフとして表す。

プレイヤーは住民一人ひとりへ経路を指示するのではなく、交通網・路線・政策・料金・容量を調整する。渋滞・所要時間・利用者数・サービス範囲を見て改善する。

### モードとネットワーク

| 移動手段 | 区間/駅の基本表現 | プレイヤーの操作 | シミュレーション |
| --- | --- | --- | --- |
| 徒歩 | 歩道、横断歩道、歩道橋、駅構内 | 歩道接続・横断位置・歩行者道 | 区間の共通移動＋横断境界の待機/許可 |
| 自家用車 | 車線/道路・交差点・駐車場 | 道路/交差点/駐車・通行規制 | 区間流量・待ち行列・駐車容量 |
| バス | 道路グラフ＋停留所＋便 | 停留所、ルート、車両、運行間隔、運賃 | VehicleIdの走行と乗客IDの乗降 |
| 鉄道 | 線路/閉塞、駅/ホーム、便 | 線路・駅・路線・車両配置 | 駅間移動イベント・閉塞/ホーム予約 |
| 地下鉄 | 地下線路、駅入口/乗換口、便 | 地下駅・線路・運行計画 | 鉄道同様、地上と接続する乗換State |
| 路面電車 | 軌道・道路交差部・停留所、便 | 軌道/停留所/運行 | 道路との競合領域と列車の停車 |
| タクシー | 道路＋乗降地点＋配車 | 営業許可・営業所・料金/政策 | 予約・迎車・乗車・降車 |
| 貨物 | 道路/鉄道/港・倉庫 | 貨物駅/倉庫/港、産業接続 | ShipmentIdの予約と配送/納品 |
| 都市外の空港/港/鉄道 | ExternalPortと便・輸送枠 | 拠点建設と運行能力 | 市内入出時だけID/貨物を明示 |

※ v1は自転車専用の走行・貸出網を必須にしない。将来の交通手段追加は境界契約を拡張する。

## 2. 出発地・目的地と交通手段選択

市民の移動は `TripId` で表し、`CitizenId`、出発/目的施設・希望到着時間・目的（通勤/通学/買物/余暇/搬送）・交通手段・現在のStateを保存する。

候補交通手段の**一般化移動費用**を比較する:

`GeneralizedCost = 走行/歩行時間 + 待ち時間 + 乗換ペナルティ + 運賃/駐車費の時間換算 + 個人嗜好補正 + 遅延リスク`

- 元々の通勤条件が同じ人の候補経路・待ち時間は集団で共有する。個人の所得・車所有・嗜好による差分のみ必要時に計算する。
- 住民は仕事や学校へ毎日同じ通勤手段を必ず選ぶのではなく、道路/公共交通の変化が一定の閾値を超えたら再選択。
- 都市内の旅行を無限に再探索しない。道路閉鎖/便遅延・待機超過・目的地閉鎖などのイベントで再探索を起動し、短時間の経路切替を防ぐクールダウンを設ける。
- 居住/就業地の近さや徒歩アクセスが悪い場合、車が増え渋滞する。鉄道やバスが遅く不便なら路線を設置するだけでは利用者が増えない。

### 経路探索の初期方式

歩道/道路グラフは有向のNode/Segment/Boundaryを持ち、接続・道路種別・制限・速度・現在の混雑と信号待ちの見込みをコストへ反映する。

- 小規模ではDijkstra/A*を基準実装。大都市では**幹線/地区の階層グラフ、OD単位のキャッシュ、変更区間の逆引き失効**を使う実装候補を性能比較で選定。
- 各IDの完全な経路ノード列を保存することを必須としない。共有可能なRouteId＋個別の現在区間・次境界・必要差分でよい。
- 鉄道/バスは運行ダイヤ・徒歩接続・乗換と容量を含む時刻依存のルート探索をする。
- 目的地まで接続がなければ `Unreachable` として理由を表示。見つからないからといってIDをテレポートしない。

## 3. 道路交通・渋滞・駐車

道路区間が保持する情報:
`SegmentId / Length / LaneCount / SpeedLimit / Occupancy / EntryCapacity / ExitCapacity / Queue / Restriction / Revision`

- 道路容量と待ち行列は**道路区間単位**で処理する。次区間へ入れるかは境界で評価し、車間距離まで全車両ごとに連続計算しない。
- 区間内の基本所要時間は距離・速度制限・混雑係数で共有計算。前方出口が詰まれば `QueuedForExit` に入り現在区間の占有を維持し、上流からの進入を妨げる（spillback）。
- 渋滞が増えると目的地までの予測所要時間が上昇し、一定の閾値を超えるとルート・交通手段を再評価する。
- 一方通行・バス専用車線・車種制限・高速道路の出入口・右左折制限はBoundaryルールで扱う。
- 住宅/商業の車は適切な駐車枠（建物付属、路上、駐車場）へ移動して帰宅/買い物完了。駐車場が満杯なら探索・待機・公共交通等への変更が起こる。
- 保守不足は速度/事故リスク/維持コストの増大として反映する。道路を改善すると周辺の建築適性・アクセスと交通量が変化する。

**路面上の車両数や渋滞は画面外でも確定した値を維持する**。カメラ移動によって車が渋滞を無視して到着したことにならない。

## 4. 信号・横断・交差点・歩道橋

基本の横断Stateは `SidewalkWalking → CrosswalkWaiting → CrosswalkWalking → SidewalkWalking`。

- 歩道を歩くStateでは横断歩道に直接進入できず、一度横断待機へ振り分ける。
- **横断を開始する前だけ**歩行信号の青/赤と容量をチェック。赤は`SignalGreen`のイベント購読。既に横断中の人は通常の赤信号で止まらない。
- 車は横断歩道の**占有者**と信号と優先・交差点の競合領域を確認して進入。人が待機しているだけの場合と実際に横断中の場合は別に扱う。
- 歩行者が退出して競合領域が空くと、待機車両へ`ConflictCleared`を送る。入場は定員・信号・優先を再確認してから許可する。
- 歩道橋/地下歩道は信号に依存せず交差できるが、移動時間・昇降の負担・施設コストがある。歩行者によって好まれない場合もある。
- 交差点では同時刻イベント順を `退出と解放 → 信号変化 → 入場` として決定的に処理。赤になった時点での新規入場は不可。

## 5. 公共交通の建設・運行

プレイヤーは「駅/停留所建設→接続ネットワーク→路線作成→車両数/運行間隔設定→予算/運賃設定」の順に運行開始する。

### バス

- バス路線は停留所の巡回順序・往復運行・車両数・運行間隔を持つ。停留所と車庫は道路に接続している必要がある。
- バスは車両IDで道路容量と信号の影響を受ける。バスレーンがあれば混雑時の優先通行が得られる。
- 停留所で `WaitingForBus → Boarding → Riding → Alighting` と遷移。満員なら乗車しなかったIDは次便待機へ戻る。運行が停止したら路線変更候補を表示する。

### 鉄道・地下鉄・路面電車

- 路線は駅・ホーム・走行区間・列車編成ID・運行ダイヤを持つ。線路の閉塞と駅ホームの占有で同じ編成を重複進入させない。
- 地下鉄は地上道路を占有しないが駅と換気・電力・維持費が必要。路面電車は道路交差点や信号と競合する。
- 乗客は駅入口→改札→ホーム待機→乗車→車内→降車→徒歩/乗換とState遷移。列車が画面外でも駅間の到着イベントで進む。
- 満員、遅延、乗換失敗は待機・代替経路・満足度へ反映。交通手段を使うだけで全員の経路探索を毎フレームやり直さない。

### タクシー、域外交通

- タクシーは空車ID・乗客予約・迎車・乗車・降車を持つ。迎車中の車両を他の客へ二重割り当てしない。
- 空港/港/都市間鉄道は外部接続Portと便・乗降容量・流入出イベントを持つ。空港の外を飛ぶ飛行機を全行程に渡り個別物理で計算しない。
- 旅客と貨物は同じ駅/港にいても**別容量・別数量の保存則**を持つ。

## 6. 物流と緊急車両の移動

- 工場・倉庫・商店・建設現場間のShipmentIdについて、積載→車両割当→道路/鉄道移動→納品を記録する。商品は在庫・輸送中・受入済のいずれか一つに属する。
- 緊急車両（救急車、消防車、警察車両）は共通道路ネットワークを使う。現実味のために交差点優先や一部の渋滞回避効果を与えられるが、閉鎖道路や物理的な容量を無条件に通過しない。
- 車両の配車は既存の施設定員・車両待機Stateを使い、同じ消防車が二つの火災へ同時出動しない。

## 7. 情報表示とプレイヤー施策

**交通情報レイヤー:** 車両交通量、混雑率、平均所要時間、横断待機、公共交通利用者・収支、路線の定時性、駐車空き、歩行アクセス、貨物流量、救急到着時間。

問題箇所を選ぶと、次の理由を表示する：信号待ち、前方容量不足、道路閉鎖、駐車不足、路線容量不足、乗換回数過多など。

プレイヤーが実行できる対策：道路拡張、交差点信号変更、右左折制限、歩行者道、歩道橋、バスレーン、路線/便増強、駐車場、公共交通料金、地区の車両規制、貨物専用接続。

道路を増やすだけが唯一の正解ではないよう、維持費・用地・誘発交通・公害のトレードオフを持つ。

## 8. 完了判定

- 同一TripIdで徒歩→バス→徒歩/鉄道乗換→目的地に到達できる。
- 横断歩道の信号・人と車の競合・部分許可・退出後の再開でIDと容量が破綻しない。
- 道路/鉄道を閉鎖すると該当する到達予約が失効し、影響IDだけ再計画できる。
- バス/列車/タクシー/貨物/緊急車両の容量・予約を二重に消費しない。
- 渋滞した道路の下流だけでなく上流も容量制約の影響を受ける。
- 住民の交通手段選択が所要時間・運賃・乗換・車所有に反応する。
- 100万人規模の都市で全車両/歩行者の物理演算を毎フレーム実行しない構造が維持される。性能基準は実測で判定する。
