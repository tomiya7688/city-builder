# 電力・上下水道・ごみ・公共サービス・環境・災害仕様 v1.0

> 完成版の都市インフラと環境のゲームルール。共通計算と状態変更の配信は [DOMAIN_INTEGRATION](DOMAIN_INTEGRATION.md)、イベントの順序・再現性は [RUNTIME_PROTOCOL](RUNTIME_PROTOCOL.md) を優先。高精度な物理演算そのものではなく、**都市に対する説明可能な効果**を設計する。

## 1. インフラの共通モデル

供給システムは「設備・接続網・需要/処理容量・停止理由・予算」を持つ。各建物の供給状態は `Available / Limited / Unavailable` に近いサービスレベルで表し、必要な個別差分を加える。

`設備が稼働→供給可能量を系統に割当→不足/過剰を計算→関係建物へ差分通知`

- 電力・水・下水・通信は接続成分（ネットワークで連結している施設群）ごとに計算。見た目の線が接しているだけでは接続と見なさない。
- ごみ・医療・消防・警察・学校は通行ネットワークでの**到達時間・施設容量**を評価する。単純な円形の半径だけでサービス可能としない。
- 設備の停止や予算変更のたびに都市の全建物を再計算せず、接続成分/サービス圏と状態の変わった建物ID集合のみ更新する。
- 容量不足でサービスを落とす場合は、優先順位/配分方針をUIで確認可能。建物が自動で隠れた「魔法の供給」を受けない。

## 2. 電力ネットワーク

### 施設と供給

発電施設の基本カテゴリ：火力（石炭/ガス）、風力、太陽光、水力。各施設は `GeneratorId, capacity, output, fuel, cost, emission, condition, availability` を持つ。容量は初期値から設定データでチューニングする。

- 火力：安定供給、燃料物流と大気汚染/維持費の負担。
- 風力・太陽光：天候・昼夜で出力変動、燃料不要。
- 水力：水域と地形の条件に左右される。全流体の高精度シミュレーションは要求しない。
- 送電線・変電施設と建物接続で系統を形成。大規模施設は設置面積と接続に制限。

需給:
`AvailablePower = 発電出力 + 蓄電放電（導入した場合） − 送配電損失`

`RequiredPower = Σ(建物用途×稼働率×時間帯別需要)`

不足なら、公共安全設備・上下水処理等の指定優先度と地区の配分政策に従い、使用可能量を配分する。停電しても建物IDは残り、`PowerLost / PowerRestored` により影響する工場・住宅・駅・浄水設備がState更新される。

**電力停止→ポンプ停止→水供給減少→建物稼働変化→電力需要減少**のような因果ループでは、同時刻の処理位相と更新の収束判定/閾値ヒステリシスを設け、無限イベント往復を防ぐ。

## 3. 上水・下水・水質

### 上水

取水施設、浄水場、ポンプ、配水管、貯水設備を建設する。取水は水域・外部供給口等に接続する必要がある。

`SupplyCapacity = 取水可能量 / 浄水能力 / 管路流量 / 電力供給` の各制約を満たす範囲で、同じネットワークの建物へ割当する。初期実装は容量付きネットワーク計算とし、全管路の連続流体物理を行わない。

水不足により住民満足度・工場稼働・消防の能力へ影響。管路工事/漏水/停電による断水は `WaterUnavailable` を差分配信。

### 下水

下水管、処理場、排水口を扱う。建物の排水量を用途・入居/稼働率から計算し、処理能力を超えた未処理量は水質汚染・衛生悪化へ反映。**下水設備は上水とは独立した接続網**とし、一方だけ接続しても両方の機能を自動的に満たさない。

雨水/洪水は地形と気象の低頻度モデルで扱い、下水処理能力・低地・防災施設に応じて浸水被害が変わる。

## 4. ごみ・リサイクル

建物用途と世帯数から、地区/用途別のごみ発生率を決める。ごみ蓄積は `A(t)=A0+rate×(t−t0)` の方式で計算可能な間はまとめて評価する。

- 建物のごみ上限に近づいたら `PickupRequested`。収集車は車両IDを持ち、道路グラフに沿って走り、道路渋滞の影響を受ける。
- 埋立場/焼却炉/リサイクル施設の受入容量・処理速度・汚染・稼働コストは別に計算。
- 回収できないごみが蓄積すると満足度・衛生・土地価値が下がる。
- 収集車・施設の定員は原子的に予約し、同じごみ量を二重回収・二重処理しない。
- 後から地区の分別政策でごみ種類や収集費用の係数を変更できる。

## 5. 通信

通信塔・基地局・通信施設でカバー範囲と帯域容量を供給。v1の通信はオンライン遊戯のためではなく、**オフィスや高密度商業・都市サービスの効率**を表す都市設備。

通信の欠落は企業生産性や魅力に影響するが、初期住宅がすぐ生活不能になるような過剰ペナルティは避ける。通信が停止した地区と建物だけ再評価する。

## 6. 医療・救急

施設：診療所、総合病院、救急車基地（病院付属も可）。診療枠・病床・救急車・医療スタッフ枠を持つ。

- 発病/事故の発生確率は年齢層・環境・地区に応じて低頻度で計算し、発生したCitizenIdのみPatientStateへ。
- `IllnessOccurred → CareRequested → FacilityAssigned → Traveling/Waiting → UnderTreatment → Recovered/Transferred`。
- 病院までの到達時間、病床空き、予算、教育水準が治療結果に影響する。設備が空きなら待機ID群を再開する。
- 救急車は道路容量・渋滞・交差点に従い、実際の到着が遅れると結果が変わる。
- 医療サービス不足は死亡率/満足度に遅れて影響。住民全員を毎フレーム診察判定しない。

## 7. 教育と研究

小学校・中学校/高校・大学/研究施設を設置。学齢・住所・交通アクセス・施設定員で通学先を割り当てる。

- 子供は6〜17歳を主に基礎教育へ、18〜24歳の一部を大学へ（初期バランス、カスタマイズ可能）。
- 学期・年度の区切りをイベントとし、入学・進級・卒業時に教育水準を更新する。
- 教育水準の高い労働者はオフィス・高度産業の求人との適合が高くなる。通学時間と学校定員は満足度と都市魅力へ作用。
- 子供が通学した時点で教育が瞬間的に最大になることはない。日単位/年度単位の蓄積を使う。

## 8. 警察・消防・事故対応

### 警察と治安

警察署は警官枠・車両・予算・到達可能区域を持つ。犯罪/事件発生のリスクは人口密度、地域環境、サービス不足、経済条件の地区平均から求める。個人に固定的な「犯罪者属性」を貼り付ける必要はない。

事件が起きた場合だけ `IncidentId` と対象施設/地域を生成し、出動→到着→対応→解決/未解決へState遷移。治安指標と地価・満足度が変わる。

### 消防と火災

消防署・消防車・消火栓などの設備を建設。火災発生確率は建物用途・密度・老朽化・防火設備・季節などを地区/建物群で評価。

`FireStarted → Reported → UnitDispatched → ArrivalDue → Extinguishing → Extinguished / SpreadDue`

- 火は画面外でも時刻イベントに従って進行。隣接建物への延焼は近傍索引から必要な範囲を評価。
- 消防車が渋滞する・水道が停止する・消防予算を下げると消火に時間がかかる。
- 被害建物は修理/再開発/取り壊しのStateへ移行し、住民は避難/一時転居を必要とする。
- 火災演出の描画粒度を落としても被害量・発生時刻は変わらない。

## 9. 公園・観光・葬祭と地域の魅力

- 公園・広場・スポーツ/娯楽施設・ランドマークは接道/徒歩アクセス・面積・維持費・利用可能人数を持ち、周辺地区の満足度/地価・観光需要を上げる。
- 観光客は外部接続から来訪予定を持つ。市内で移動する場合は必要なVisitorIdを作成し、帰るときにExternalPortで移管する。
- 高齢化・死亡は住民ライフサイクルで扱い、葬祭施設に定員/車両/待機のStateを設ける。死亡時に人数・世帯・雇用・居住枠を正しく解放する。
- 地区の快適性と公園の効果は周辺のサービス圏で計算し、施設のすぐ隣だけに突然明確な境界を作らないよう距離/アクセスで減衰させる。

## 10. 環境・天候・自然災害

### 汚染

大気・騒音・土壌・水質を区別し、地形/地区の粗いグリッドで蓄積・拡散・自然吸収・除去を更新する。産業、発電、道路、処分場、排水が主な汚染源。風や水流は次の低頻度評価へ影響。

地価・健康・満足度・教育への効果を持たせる。影響を受ける区画/施設の差分だけ通知する。

### 天候・季節

昼夜・春夏秋冬・晴天/雨/雪/強風・気温の状態を持つ。ゲーム内時刻のイベントに応じて電力需要、発電出力、交通所要時間、災害リスク、観光需要を補正。

気象の視覚表現はUI担当、天候による道路所要時間や供給量の最終判断はProcess担当。

### 災害

発生をプレイヤーがOFF/低/通常/高に設定可能。基本カテゴリは火災、大雨/洪水、暴風、地震。災害は施設/道路/送電/配水の一部を停止し、避難/復旧費用へつながる。

- 原因、影響範囲、被害レベル、復旧予定のStateを持ち、画面外でも発生・進行・復旧する。
- 道路閉鎖では影響する走行予測を失効させ、移動IDを待機/迂回へ振り分ける。
- 災害発生率はシナリオ条件とseedによって再現可能。サンドボックスは災害OFFでも成長できる。
- 復旧には資金、稼働している工事/消防/医療等の容量と時間が必要。復興の達成がシナリオ目標にもなる。

## 11. 施設の情報表示

施設をクリックすると**接続/担当範囲、稼働率、容量、待機件数、維持費、現在の問題、予測効果**を表示。

電力なら「発電不足」「系統が繋がっていない」、下水なら「管路が途切れた」、病院なら「満床」「渋滞で救急車到着遅延」など、問題の**原因を具体的に見せる**。通知の多重発火は原因ID/地区でまとめる。

## 12. 完了判定

- 住宅/工場が停電/断水/下水不足になると稼働率・需要・都市の財政/満足度へ影響し、復旧で回復する。
- 医療/教育/消防/警察は施設の定員と到達時間を使い、車両と患者/生徒IDの重複予約がない。
- 汚染・天候・洪水・火災が画面外でも進行し、同じseedで再現可能。
- 系統/施設の停止イベントが循環しても無限イベントループにならず、対象地域のみ再計算する。
- サービス予算・道路アクセス・施設位置の改善がプレイヤーの都市運営へ理解できる形で返る。
