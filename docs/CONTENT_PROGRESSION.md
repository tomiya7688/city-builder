# コンテンツカタログ・解放・シナリオ仕様 v1.0

> **完成版v1の採用範囲**。施設ごとの厳密な供給能力・建築費・維持費は調整可能なデータとして管理し、初期値は [GAME_BALANCE_RELEASE](GAME_BALANCE_RELEASE.md) へまとめる。建築/住民のStateは共通の[実行契約](IMPLEMENTATION_SPEC.md)に従う。

## 1. コンテンツの原則

プレイヤーが置く施設・道路・区画と、自動的に成長する建物を区別する。一般の住宅/商店/工場/オフィスの大部分は用途区画から需要と立地条件に従って発生し、公共施設・交通・発電・上下水・ランドマーク等はプレイヤーが直接配置する。

**施設タイプ数をクラス数にしない。** 施設は共通のデータ定義で用途、接続、容量、更新条件、コスト、見た目、受入イベントを持ち、異なる計算が必要な場合だけ別の責務/ルール契約へ移譲する。

### ゾーンと建物

- **住宅**：低/中/高密度。住戸型・外観・レベル1〜3。地価と公共サービスに反応。
- **商業**：低/高密度。小売、飲食、娯楽をベースに店舗カテゴリを持つ。
- **工業**：一般工業と、農業・林業・鉱業の専門産業。
- **オフィス**：標準/高密度。教育・通信/電力の需要が高い。
- 建物アセットは、各密度/用途に**最低3外観バリエーション**を用意する。レベルによる見た目変更や増築パーツで反復を抑える（最終的なモデル数はアート制作工程で確定する）。
- 建物は `templateId` を持ち、費用、入居/職場容量、電力/水/ごみ需要、污染、成長条件、接道条件、税の扱いを持つ。

## 3. データ定義と拡張契約

建物・道路・設備・ポリシーはプログラムに値を散らばらせず、**バージョン付きUTF-8データファイル**を基本とする。初期候補はJSON。ゲーム本体では読込時にスキーマ・参照・数値範囲を厳密に検証する。

施設テンプレートの必須フィールド:

`id, category, displayNameKey, descriptionKey, iconKey, footprint, connections, buildCost, upkeepPerDay, capacities, utilityDemand, pollutionOutput, allowedTerrain, unlockRuleId, visualLodSet, behaviorRuleIds, dataVersion`

- `id` はセーブデータに使うため安定。別IDへ変更する際は移行規則を定義する。
- `capacities`、需要、コストは単位（人、世帯、MW、m³/day、Credit/day等）を明示。
- 行動はコードを埋め込む任意実行スクリプトではなく、ホワイトリスト化した `behaviorRuleIds` を参照する。
- 読込失敗・参照欠損・負値/範囲外は安全なバリデーションエラー。実行中に都合のよい0へ黙って変換しない。
- v1の外部追加コンテンツは**データと画像/音のコンテンツパック**に限る。任意のJVMバイトコード/スクリプト実行、ファイルシステム外へのアクセスを初期の公開Mod APIとして提供しない。
- コンテンツパック名・バージョン・ハッシュをセーブへ記録し、読込時に不足と非互換を表示する。

### コアとアートの分離

同じ建物のテンプレートはUIの見た目/アニメーションが変更されても、Processの容量・State・資源・財政を変えない。外観バリエーションを増やすだけでシミュレーションオブジェクトを増やすことを要求しない。

## 4. サンドボックスの解放・モード設定

- **通常サンドボックス**：都市成長に応じて機能が段階的に解放。
- **全解放サンドボックス**：全機能を初期から建設可能。災害/資金/サービス難度を個別設定可能。
- **シナリオ**：設定済みの都市または初期マップから、目標・制約・難度と指定された解放を使う。

### マイルストーン初期案

| 人口 | 新たな中心要素 | 補助条件（満たせない場合は理由表示） |
| ---: | --- | --- |
| 0 | 基本道路/歩道、低密度住宅・商業・工業、基本電力/上下水、区画 | 外部道路接続 |
| 100 | 公園、小型診療所、基本予算・税率調整 | 住宅の稼働 |
| 1,000 | バス、学校、消防・警察、ごみ処理 | 納税と道路の接続 |
| 5,000 | 中密度住宅、オフィス、地区政策、リサイクル、鉄道 | 雇用・教育・財政の一定水準 |
| 20,000 | 高密度住宅/商業、地下鉄、路面電車、病院/大学 | 交通の接続と高密度地区のインフラ |
| 100,000 | 空港・港、専門産業の高度化、災害対策大型設備 | 財政・域外交通・資源/土地条件 |
| 500,000 | 大型ランドマーク、路線/物流の高容量更新 | 雇用・交通・住民満足度 |
| 1,000,000 | メガシティ記念目標と都市評価の最終実績 | 人口達成だけで固定エンディングにはしない |

例外：都市の存続に必須な電気/水/下水などはマイルストーン達成まで封鎖しない。災害対応に最低限必要な施設も、問題を発生させる前に解放する。

## 5. シナリオ5本（完成版に含める）

シナリオは同一エンジンの設定と目標条件で定義し、専用の別ゲームループを作らない。

| 名称（仮） | 開始条件 | 達成条件 | 失敗条件 |
| --- | --- | --- | --- |
| はじめての街 | 平原・人口0・通常資金 | 人口1,000、電気/水道の供給率95%以上、7日連続収支非負 | なし（学習用） |
| 朝の大渋滞 | 住宅地と工業地が遠い既設都市 | 対象幹線の通勤時間を開始時比30%改善し、利用者の満足度60以上を7日維持 | 指定予算を使い切り、改善不能になった場合 |
| 緑の工業都市 | 工業比率が高く汚染が大きい都市 | 空気汚染指標30%減、産業雇用90%以上維持、14日連続黒字 | 産業雇用が開始時の60%を下回る状態が7日 |
| 川沿いの復興 | 河川氾濫で一部の設備が停止 | 必須インフラ90%復旧、避難者80%以上帰宅、30日以内 | 30日で目標未達 |
| 財政再建 | 赤字の既設都市 | 負債を所定額以下、税収/支出比が健全で14日連続黒字、人口流出を抑制 | 破綻条件を30日連続満たす |

**数字は初期の難度設定**であり、初期マップと設備の価格を使って達成可能かプレイテストで検証する。シナリオ進捗はUIで常に確認でき、達成後もサンドボックスとして続行可能。

## 6. 難易度

Easy / Normal / Hard は初期資金係数、建設・維持費係数、税収係数、ローン条件、災害発生率にのみ作用する基本方針。交通の信号安全性・IDの同一性・セーブ整合性・カメラ不変性は難易度で変更しない。

| 難度 | 初期資金倍率 | 維持費倍率 | 税収倍率 | 自然災害 |
| --- | ---: | ---: | ---: | --- |
| Easy | 1.5 | 0.8 | 1.1 | 低 |
| Normal | 1.0 | 1.0 | 1.0 | 通常 |
| Hard | 0.7 | 1.2 | 0.9 | 高 |

スタート資金はNormalで500,000 Credit。災害は難度の推奨値から個別にOFFへ変更可能（特定シナリオ以外）。

## 7. コンテンツとゲームの品質基準

- 施設ごとに建設・運営・停止・撤去・セーブの全Stateを扱い、表示上は配置できてもProcessで無効な「飾り施設」を必須ゲーム要素にしない。
- チュートリアルと初期マップは、最低限の施設で電力・水道・下水・仕事を確保できるように構成。
- 施設を選択したとき役割・供給能力・問題・毎日の維持費が分かる。
- 同一のテンプレート定義を、建設UI、Processの施設ルール、Dataの保存版参照が整合的に使用する。
- ゲーム内テキスト・アイコン・音・アート資産のライセンスを管理し、第三者ゲームの地名・商標/アセット・画像や音楽をそのまま転用しない。
